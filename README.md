# 公益站自动签到助手

一个基于 Chrome Manifest V3 的多站点签到扩展，用于统一管理公益 API
站点的手动签到、每日定时签到、登录签到和页面访问任务。

项目无需构建、无需安装依赖，下载后可直接以“已解压的扩展程序”加载到
Chrome。站点配置、认证缓存和签到结果均保存在浏览器本地。

> [!WARNING]
> 自动签到依赖目标站点当前的页面结构、接口协议和登录策略。站点升级、
> Cloudflare 验证或风控策略都可能导致任务失败；使用 API 模式前请自行评估
> 账号风险。

## 支持的站点类型

| 类型 | 典型签到方式 | 认证方式 |
| --- | --- | --- |
| NewAPI | `/api/user/checkin` | 浏览器登录态、缓存认证头、Linux.do OAuth |
| Sub2API | `/api/v1/user/check-in` | 页面本地存储中的 token |
| ZenAPI | `/api/u/checkin` | 浏览器登录态、Linux.do OAuth |
| Infinite Canvas | `/api/auth/check-in` | Linux.do OAuth、本地持久化 token |
| DEEIX Chat | `/api/v1/billing/checkin`（站点开放时） | 刷新登录态、Linux.do OAuth |
| LocalAPI | `/user/api/checkin` | `localapi_user_token`、`x-user-token` |
| points-checkin | `/api/points/checkin` | Cookie 会话、Linux.do OAuth |
| 通用页面签到 | 查找并点击“签到 / 签 / Check in”等按钮 | 浏览器现有登录态 |
| 仅访问站点 | 每日打开指定页面并读取可用余额 | 浏览器现有登录态 |

`points-checkin` 适用于 WisArt 等使用相同协议的站点。扩展也支持自动探测
站点类型；如果站点使用了深度定制的接口或页面，可能需要改用页面模式，或
提交 Issue 补充适配。

除普通签到外，还可以为站点选择以下运行模式：

- **按钮/API**：执行接口签到，或在目标页面点击签到按钮。
- **仅访问**：只访问指定页面，不执行签到请求。
- **登录签到**：复用现有登录态完成每日登录。
- **重登签到**：重新建立登录态后完成登录任务。

## 主要功能

- 多站点统一管理，支持启用、禁用、分组和拖拽排序。
- 默认每天 `09:00` 自动执行，也可自定义签到时间。
- 支持立即签到、从指定站点继续、失败站点单独重试和运行中终止。
- 自动识别站点类型，并按类型选择对应的认证与签到流程。
- 支持 API 与页面点击两种执行方式，接口受限时可回退到页面上下文。
- 自动复用浏览器登录态；必要时尝试 Linux.do OAuth。
- 展示成功、已签、失败、失效等状态，并在本轮可读取时展示余额。
- 支持配置导入、导出，以及在站点签到按钮旁快速加入或移出扩展。
- 后台标签页静默执行，任务结束后自动关闭，不主动抢占当前页面。
- 所有用户数据保存在 Chrome Storage，不上传到额外的第三方服务。

## 安装到 Chrome

1. 下载或克隆本项目，并确保目录结构保持完整。
2. 在 Chrome 地址栏打开 `chrome://extensions/`。
3. 打开页面右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”（Load unpacked）。
5. 选择本项目中的 **`chrome-extension` 文件夹**。
6. 建议将扩展固定到浏览器工具栏，方便查看签到状态。

更新本地代码后，需要回到 `chrome://extensions/` 点击扩展卡片上的“重新
加载”，否则 Chrome 仍会运行旧版本。

## 简单使用

1. 先在 Chrome 中登录需要签到的目标站点。
2. 打开扩展，点击“添加站点”，填写站点签到页的完整地址。
3. 根据站点用途选择“按钮/API”“仅访问”“登录签到”或“重登签到”。
4. 普通签到站点可按需开启 API；不确定时优先保留页面模式。
5. 点击“立即签到”，扩展会依次处理所有已启用站点并实时更新结果。
6. 在“每日签到”中设置自动执行时间；需要迁移时使用“导出配置”。

访问已存在签到按钮的站点时，扩展也会尝试在按钮附近显示“加入签到助手”
入口，可用它快速添加当前站点。

## 整体设计

```text
+----------------------+       +----------------------+
| Popup / page entry   |       | Chrome alarm         |
| add, manage, run     |       | daily schedule       |
+----------+-----------+       +----------+-----------+
           |                              |
           +--------------+---------------+
                          |
                          v
               +----------+-----------+
               | Task orchestration   |
               | queue, retry, timeout|
               +----------+-----------+
                          |
              +-----------+------------+
              |                        |
              v                        v
     +--------+---------+     +--------+---------+
     | visit/login mode |     | check-in mode    |
     | open target page |     | detect site type |
     +--------+---------+     +--------+---------+
              |                        |
              |              +---------+----------+
              |              |                    |
              |              v                    v
              |     +--------+---------+  +-------+----------+
              |     | type handler/API |  | page button      |
              |     | auth + request   |  | fallback         |
              |     +--------+---------+  +-------+----------+
              |              |                    |
              +--------------+---------+----------+
                                       |
                                       v
                            +----------+-----------+
                            | Chrome Storage       |
                            | config/results/cache |
                            +----------+-----------+
                                       |
                                       v
                            +----------+-----------+
                            | Popup status refresh |
                            +----------------------+
```

一次普通签到的核心逻辑如下：

1. 读取已启用站点，并检查站点是否可访问。
2. 对 `auto` 类型站点进行探测，并保存识别结果。
3. 从加密缓存、浏览器登录态或 OAuth 中获取认证信息。
4. 按站点类型执行专用接口；页面模式则打开签到页并查找按钮。
5. 遇到可重试失败时最多执行三次，每次都有独立超时保护。
6. 尝试读取本轮余额，保存结果并刷新扩展弹窗。
7. 关闭任务创建的临时后台标签页。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `cookies` | 读取目标站点和 Linux.do 的现有登录态 |
| `storage` | 保存站点配置、运行结果和加密认证缓存 |
| `alarms` | 创建每日自动签到任务 |
| `tabs` | 打开和关闭任务所需的后台页面 |
| `scripting` | 在页面上下文中读取状态、余额或点击按钮 |
| `webRequest` | 捕获目标站点请求中的必要认证信息 |
| `https://*/*` | 访问用户主动添加的 HTTPS 站点 |

权限范围较大是因为扩展需要适配用户自行添加的不同域名。请只从你信任的
源码构建或加载本扩展。

## 项目结构

```text
auto-sign/
|-- README.md                 GitHub 项目说明
`-- chrome-extension/         在 Chrome 中 Load unpacked 时选择此目录
    |-- manifest.json         Manifest V3 扩展清单
    |-- background.js         签到编排、认证和页面兜底
    |-- popup.html            扩展弹窗
    |-- popup.js              站点管理与状态展示
    |-- config.js             站点配置与类型映射
    |-- schedule.js           每日定时逻辑
    |-- import-entry.js       页面内快速添加入口
    |-- backup-config.js      配置导入导出
    |-- *-auth.js             各类认证辅助模块
    |-- balance.js            余额解析
    `-- icons/                扩展图标
```

项目使用原生 JavaScript、HTML 和 Chrome Extension API，没有构建步骤或
第三方服务端依赖。

## 隐私与风险

- 认证信息可能包含 Cookie、token 或请求头，扩展只在本地使用这些数据。
- 认证缓存会加密后写入 Chrome Storage，但不应将浏览器配置或导出数据公开。
- API 和页面结构由各站点维护，兼容性无法永久保证。
- 高频请求可能触发站点限制；请使用合理的执行时间和站点数量。
